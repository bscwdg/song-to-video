# v0.1 代码审查与 v2 方向

审查对象：`song-to-video` @ `4791fb9`（0.1.0）
审查方式：通读源码、模板、两个案例的 timing/分镜/QA 记录。仓库内没有音频与 `node_modules`，未重新渲染，结论基于代码与已提交的验收数据。

## 一句话结论

v0.1 的**工程骨架是合格的**（时间轴单一来源、纯函数画面、codegen、规格 QA、媒体不入库），但它现在是一个**手工剪纸动画工地**，不是"歌生视频"。

真正的瓶颈不在渲染，而在三处：

1. 音乐只用了"拍"，没用"小节 / 段落 / 能量"；
2. 画面没有镜头语法，每首歌要从零写 2000–2800 行场景代码；
3. 九个镜头其实是同一个舞台的九个机位，纸偶没有关节、纸张没有层深。

---

## 一、它现在是什么

| 项 | 事实 |
|---|---|
| 入口 | 复制模板 → 手写切点 → 手写分镜 → 手写 9 个场景 → 渲染 |
| 声音事实 | `analyze_track.py`（351 行）只产出 duration / BPM / beats / 歌词 / cues |
| 可复用画面 | 模板只有 `world` 和 `split` 两个通用场景 |
| 案例规模 | `money-girl` 2844 行 / 9 镜；`papercut-song` 2125 行 / 9 镜 |
| 交付 QA | 编码、分辨率、帧率、时长四项 |

也就是说：**"生视频"的部分是人和 Agent 的即兴创作，代码只负责把它钉到拍点上。**

---

## 二、七个结构性问题（按影响排序）

### 1. 只有"拍"，没有"小节 / 段落 / 能量"

`analyze_track.py:194` 只调用一次 `librosa.beat.beat_track`，然后：

- 没有 downbeat，没有 `beats_per_bar`；
- 没有 section（主歌/副歌/桥段）；
- 没有 onset、spectral flux、频段能量、RMS 包络；
- 没有 tempo confidence，也没有倍频校验。

后果一：**所有画面反应都是同一个 `beatPulseAt` 指数衰减**，不管这一拍是底鼓、是人声字头，还是空拍。卡是卡上了，但不"跟着音乐"。

后果二：**切点只吸到最近的拍，不吸到小节**。`money-girl` 实测：

- 拍间隔 0.3715s（161.499 BPM，86 拍）
- 九个镜头长度折算：8.7 / 7.1 / 9.1 / 9.1 / 7.0 / 8.2 / 8.1 / 9.1 / 20.2 拍

如果真实速度是 80.75（librosa 常见的倍频误判），每镜本该正好 1 小节；现在是 7、8、9 拍混着走，**每 2–3 秒就漂半拍**。观众说不清哪里不对，但会觉得"剪辑没踩在重音上"。

后果三：161.5 BPM 这个数值本身值得复核。用 `librosa.beat.plp` + tempogram 做一次倍频判定，几行代码就能确认是 161/80 还是别的。

### 2. 没有镜头语法，每首歌重写一遍

模板 1160 行里只有 `world` / `split`；两个案例各 2000+ 行、九镜全是定制 TSX。`Banknote`、`Cup`、`House`、`Doorway` 在两个案例里各写一份。

这不是"模板 + 案例"的分离，这是**每个项目复制一份引擎再改**。结果是：

- 新歌的成本 = 一次完整美术与动画开发；
- 质量取决于当次 Agent 的即兴水平，不可复现；
- 风格一旦换歌就散架，无法做 A/B。

### 3. 九镜其实是同一个舞台的九个机位

`money-girl` 九个场景的骨架高度同构：

- 6 镜使用完全相同的 `1.02 + easeInOutCubic(...) * 0.05..0.08` 推镜；
- 2 镜是横移，1 镜是升降，1 镜是旋转；
- 4 镜是"居中一对纸人 + 两侧群演剪影 + 飘落的钱"；
- 全部 `viewBox="0 0 1920 1080"`，机位只改了几何参数。

`STORYBOARD.md` 声称九条构图轴不同，实际是**同一台木偶戏换了九块背景板**。这就是"第一版不够理想"最直观的来源。

### 4. 纸偶没有关节，纸没有层深

- `PaperFigure` 是静态 group，只有新娘手里的花束随 `arm` 转 8°；没有头/肩/髋关节、没有走位循环、没有次级动作（头纱、衣摆）。
- 所有元素在同一个 `<g>` 里吃同一个 camera transform，前景与背景没有视差；`PaperBokeh` 只是装饰。
- 剪纸的签名语言恰恰是**分层 + 遮挡 + 层间阴影**。现在是单层贴纸，所以"纸感"只停留在滤镜。

### 5. 歌词系统只有"一行显示"

`analyze_track.py:272` 用下一句 LRC 起点当本句终点，`Lyrics.tsx` 只做淡入淡出：

- `money-girl` 的 `[24.49]数钱吧女孩没日没夜` 会一直挂到 `30.49`，**6 秒不动**；
- `whiteSpace: "nowrap"` + 固定 54px + `bottom: 58`，长句没有换行与安全区；
- 没有逐字/逐词时间，做不了卡拉 OK 高亮；
- 没有器乐间奏自动隐藏、没有两句对唱、没有按镜头换排版。

字幕是 MV 的第二主角，现在是最弱的一环。

### 6. 混音与 QA 只到"规格正确"

`Soundtrack.tsx:21` 用 `endAt` 硬切 BGM，没有淡入淡出、没有响度归一化、没有真峰值限制；SFX 固定 0.04–0.06，没有让位给 BGM 的包络。QA 记录里 mean −10.6 dB，对平台投放偏热且不可复现。

`qa_video.py` 只查编码/分辨率/帧率/时长。SKILL 里"每拍必须有可见变化"这条硬规则**没有任何机器检查**：

- 没有逐拍帧差 → 死拍发现不了；
- 没有 blackdetect / freeze 检测 → 切点黑帧发现不了；
- 没有字幕越界检测；
- contact sheet 只取每镜中点，正好避开所有问题帧。

所以它可以在"画面 3 秒没动"的情况下报 PASS。

### 7. 只有 16:9，坐标写死

九镜全部硬编码 `1920×1080` 绝对坐标，文档也承认竖屏要重做。而歌生视频的主战场是 9:16。这不是"改两个数字"，是**没有布局抽象**。

## 三、v2 应该长成什么样

把"生成"拆成四层，每层只产出一个可审的文件。

### L0 声音事实（确定性）

`analyze_track.py` 扩成 `song.json`：

```jsonc
{
  "tempo": {"bpm": 80.75, "confidence": 0.93, "octave": "half"},
  "beats": [...], "downbeats": [...], "beatsPerBar": 4,
  "sections": [{"start": 0, "end": 12.3, "type": "verse", "energy": 0.42}],
  "beatFeatures": [
    {"t": 0.16, "rms": 0.31, "low": 0.52, "mid": 0.2,
     "high": 0.1, "flux": 0.71, "strength": 0.83}
  ],
  "phrases": [{"start": 0.41, "end": 3.0, "fromLyric": true}]
}
```

新增：倍频校验、downbeat、小节表、段落 novelty、逐拍能量/频段/flux。这样画面才能区分"重拍抬升、弱拍呼吸"。切点默认吸到**小节**，而不是最近的拍。

### L1 剪辑决策（可审、可改）

`song.json` → `shots.json`：

```jsonc
{"shots": [
  {"id": "s01", "startBar": 0, "bars": 2,
   "archetype": "establish_wide", "subject": "couple",
   "metaphor": "money-rain", "palette": "wine-gold",
   "motion": "slow_push", "intensity": 0.3,
   "lyrics": [0, 1], "sfx": "paper-rise"}
]}
```

这一层就是现在缺失的"导演"：按段落定能量曲线，按歌词乐句定镜头数，按隐喻库选 archetype。输出 `STORYBOARD.md` 供人确认。**人只审这张表，不审代码。**

### L2 镜头库（参数化，不再每歌重写）

10–14 个 archetype，每个 3–5 个插槽，全部使用归一化舞台坐标 + 三层深度：

| archetype | 用途 | 可变槽 |
|---|---|---|
| `establish_wide` | 建世界 | 地平线、主光、群演密度 |
| `corridor_depth` | 纵深/进入 | 门洞数、雾层、视差强度 |
| `split_curtain` | 分离/转场 | 撕口形状、左右材质 |
| `iris_push` | 主观/回忆 | 圆孔位置、内景 |
| `radial_top` | 群像/仪式 | 环数、旋转方向 |
| `profile_table` | 关系/对峙 | 人数、桌面角度 |
| `macro_object` | 情绪插入 | 物件、手部姿势 |
| `crowd_grid` | 时间流动 | 行列、错拍算法 |
| `silhouette_light` | 升华/告别 | 光源形状、逆光强度 |
| `vertical_reveal` | 上升/下降 | 层数、速度曲线 |
| `pov_hands` | 主观动作 | 左右手、物件 |
| `landscape_pan` | 空间交代 | 远近景比例 |

镜头内部补齐三件事：

1. **深度**：bg/mg/fg 三层各自视差 + 遮挡 + 层间阴影；
2. **关节**：`PaperPuppet` 有头/肩/髋三个枢轴，走位用循环相位，不用逐帧手写；
3. **一个 hero motion**：每镜只允许一个主运动，其余元素只做跟随与呼吸。

### L3 渲染、字幕、混音、QA

- 字幕引擎：句时长上限、自动换行、安全区、可选逐字高亮、器乐段自动隐藏；
- 混音总线：BGM 响度归一到 −14 LUFS、首尾淡入淡出、SFX 触发时 BGM 轻微 ducking；
- QA 增加：逐拍帧差（死拍清单）、切点黑帧/冻结帧、字幕 bbox、EBU R128、逐秒 contact sheet；
- 布局：`Layout` context + 归一化坐标，同一套 archetype 出 16:9 / 9:16 两版。

## 四、实施顺序（按性价比）

| 阶段 | 内容 | 产出 | 估时 |
|---|---|---|---|
| P0 | 倍频校验 + downbeat + 小节 + 段落 + 逐拍特征；切点改为吸小节 | `song.json` v2 | 1–2 天 |
| P1 | 自动 EDL 提案（段落×乐句→镜头数与时长） | `shots.json` + `STORYBOARD.md` | 1 天 |
| P2 | 镜头库 8 个 archetype + 三层深度 + 纸偶关节 | 可复用 `shots/` | 3–5 天 |
| P3 | 用 money-girl 重做一版，与 v1 逐镜 A/B | 对照片 | 1–2 天 |
| P4 | 字幕引擎 + 混音总线 + QA 死拍/响度 | 交付级 | 1–2 天 |
| P5 | 9:16 布局 | 竖屏样片 | 2 天 |

P0+P1 不改变任何画面，只让"剪得对"；P2 才解决"好不好看"。**建议先做 P0/P1，因为它们可验证、可回滚，且立刻改善观感。**

## 五、验收标准（v2 必须能过）

1. 换一首没听过的歌，30 分钟内出 `song.json` + `shots.json` + 分镜表，人工只改不超过 3 个字段；
2. 所有切点落在小节线，误差 < 1 帧；
3. 逐拍帧差报告里"死拍"为 0；
4. 同一 archetype 在两首歌里出现时，构图参数不同、骨架相同；
5. 9:16 与 16:9 共用一套 archetype，无坐标重写；
6. QA 能对"3 秒静止画面"报 FAIL。

---

## 六、需要你定的三件事

1. **"不够理想"主要指哪一层？** 画面质感 / 剪辑卡点 / 自动化程度 / 画幅与风格适配。
2. **目标是哪种产品？** 任意歌一键出片，还是半自动、每首精修到可发布。
3. **画面允许引入 AI 吗？** 纯程序化 SVG，还是 Seedream 关键帧 / Seedance 片段与剪纸叠加。

另外，**最快缩小差距的办法是给我一支你认为"理想"的参考 MV**。现在的分镜规则是从纸潮案例反推的，没有外部标尺；有参考片，我可以直接拆它的镜头语法，而不是继续自证。
