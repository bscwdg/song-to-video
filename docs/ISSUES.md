## 一、阻断性问题（决定这套东西能不能用）

### I-01 画面与歌词内容无关 ★ 最严重

**现象**
用户反馈：「都没有根据歌词去绘图」「这和我想要的不一致」。

每句歌词对应的画面实际是：

| 歌词 | 实际画面 |
|---|---|
| 心爱的女孩她已经很如愿了 | 落日湖面 + 纸人 |
| 今年我会举办场婚礼 | 落日湖面 + 纸人（**同一镜**） |
| 也许我们一样在舞台上放声大哭 | 落日湖面 + 纸人（**同一镜**） |
| 数钱吧女孩没日没夜 | 纸门纵深 + walker（**画面里没有钱**） |

0.41–6.03 的 5 句全部落在同一个 6.99 秒镜头里。

**证据**
`skills/papercut-mv/scripts/direct.py` 第 215–225 行：

```python
archetype = pick_archetype(pool, ...)                    # 只按段落能量选池
camera    = CAMERAS[archetype][shot_index % len(...)]     # 镜号取模
palette   = PALETTES[shot_index % len(...)]               # 镜号取模
subject   = subject_pool[shot_index % len(subject_pool)]  # 镜号取模
metaphor  = metaphor_pool[shot_index % len(metaphor_pool)]# 镜号取模
```

`shot_index % len()` = 按镜号轮转。歌词文本不参与任何决策。

**更糟的一条**：`subject` 与 `metaphor` 在渲染层**根本没被读**。

```
grep subject  src/engine/archetypes.tsx  → 1 处（只有类型声明，第 26 行）
grep metaphor src/engine/archetypes.tsx  → 2 处（只有类型声明，第 28 行）
```

五个构图各自画固定的东西（落日 / 纸门 / 拱窗 / 纸环 / 花瓶），与这两个字段无关。
这属于"声明了却不消费"，与之前批评 `ObjectMacro` 的 `intensity` 是同一类错误。

**根因**
v2 为了"参数化、可复用"，把 v1 那套按歌词手写的场景（`examples/money-girl/src/scenes/MoneyScenes.tsx` 里的 `SceneMoneyRise` / `SceneStageTears` / `SceneToast` / `SceneHandsMacro` / `SceneFarewell`）整个丢掉了，换成 5 个通用构图。

**状态**
未修。这是重做的主要理由。

### I-04 画面动效生硬

**现象**
用户反馈：「画面动效太生硬了」。

**证据（实测 AI 样片 276 帧）**

```
within-shot diff: mean=2.09  median=1.10  max=146.67  std=8.89
cut        diff: 81.6 / 63.8 / 69.9
```

**镜头内部的帧差峰值 146.67 比切点的 81.6 还大** —— 镜内跳变比换镜头更剧烈。

shot 01 逐帧剖面（每 3 帧取样）：

```
0.44 0.91 1.05 0.44 0.69 0.82 1.30 0.92 1.17 1.36 1.09 1.38 1.39 [3.94] 0.97 1.01 0.97 [3.58] 0.38
```

锯齿状：每拍冲到 4 倍，然后掉到 0.38（接近静止）。

**根因（三条）**

| # | 病灶 | 机制 |
|---|---|---|
| 1 | `beatPulse` 是纯指数衰减，**没有起振段** | 一帧内从 0.2 跳到 1.0，速度不连续 |
| 2 | 光带 `(time * 0.55) % 1` **回绕时瞬移** | 从右边缘一帧跳回左边缘，每 1.82s 一次 |
| 3 | 三套运动（缓动镜头 / 拍脉冲 / 小节脉冲）**各自叠加** | 没有统一平滑，位移速度突变 |

**状态**
**方案已写但未接入**：`examples/v2-lab/src/ai/motion.ts` 实现了
- `buildEnvelope()`：一极点包络（攻击 0.13s / 释放 0.46s），替换尖峰脉冲
- `lightPass()`：单次单向扫光 + 两端淡入淡出，消除回绕瞬移

**未做**：`AiShot.tsx` 仍在用旧的 `beatPulse` + 回绕光带。

## 二、质量问题（不影响出片，但影响观感）

### Q-01 风格/角色不一致

4 张锚图实测：

| 镜头 | 底色 | 人物 |
|---|---|---|
| 01 抱钱 | 酒红 | 少女，红裙 |
| 02 婚礼 | **奶油白（明显更亮）** | 两个极小纸人 |
| 03 舞台 | 深红 + 金 | 长发女性，白裙 |
| 04 旧屋 | 酒红 | 一群小人 |

01→02 底色差太远，剪在一起会跳。角色也不是同一个人。

**根因**：每张图独立采样，共享 prompt 不足以锁定外观。
**正确做法**：首张作参考图走 image-to-image。
**阻塞**：`generate.js` 只接受 URL 或 base64，本地图转 base64 会超 Windows 命令行长度限制（实测 168KB 参数报「文件名或扩展名太长」）。需写 Node 包装脚本直接 POST。

### Q-02 无真实分层视差

当前 AI 镜头只是「一张图 + 推镜 + 扫光」，不是纸片分层动画。
**正确做法**：Seedream Pro 的 `layer_decomposition` 把图拆成 1 底图 + 最多 16 透明图层（带 `z_index` / `bounding_box`），再按深度做视差。
**状态**：**未实测**，不确定对复杂剪纸图拆得干净与否。

### Q-03 画面太素（程序化版本）

```
程序化版：mean diff 0.342  median 0.064  max 35.7
AI 版    ：mean diff 1.755  median 0.861  max 111
```

AI 版运动量是程序版的 5–13 倍。之前反复修的"死拍"问题，本质是**画面信息密度不够**，调脉冲参数治不好。

### Q-04 倍频校验没有判别力

161.499 BPM 的判定结果：

```
octave = "same"  reason = "salience-agrees"  confidence = 0.3464
salience: half 0.338 / same 0.3464 / double 0.3156
```

三者相差不到 3%，`confidence` 等于"三者几乎一样"。**这个检测没有证据力**：它没判成误判，但也没证实。之前担心的"161.5 可能是半速误判"仍未解决。

### Q-05 意象词表命中率约 50%

对 18 句歌词人工标注意象：

- 具体意象（能匹配道具）：6 句
- 动作意象（只能匹配动作）：3 句
- 抽象句（匹配不到）：9 句，如「心爱的女孩她已经很如愿了」「以前的混蛋心里面」

**一半是抽象句**，词表匹配到不了。缺的是"每首歌的导演解读"（这句唱的是她终于熬出头了 → 用婚礼拱门+纸钞雨），不是词表能解决的。

## 三、环境限制（不是 bug，但方案必须迁就）

### E-01 无 AgentPlan 视频生成权限

Seedance 全部模型报 `UnsupportedModel`（404）。Key 有效，是账号未开通视频生成。

**后果**：做不了 AI 视频片段，只能「Seedream 静帧 + 程序做运动」。

### E-02 Seedream Lite 文生图不可用

`--model lite` 报同样 404。普通文生图必须 `--model pro`。

### E-03 Seedream 生成耗时

实测 Pro 单张 2K：41.9s / 68.4s / 53.9s / 53.5s（约 50–70 秒）。
18 句歌词各出一张 ≈ 20 分钟。成本要求"先确认再批量生成"。

### E-04 Remotion 自带 ffmpeg 是精简版

只带 50 个滤镜，无 `fps` / `ebur128` / `volumedetect`，无 `rawvideo` muxer。
帧解码走 `scale` + PNG 序列；响度用 BS.1770 系数自算。

## 四、修复优先级建议

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | I-04 动效平滑 | 方案已写好，接入即可验证，成本最低 |
| 2 | I-02 AI 开关 | 用户明确要求，改主入口一处 |
| 3 | I-03 片段选择 | 用户明确要求，交互层 |
| 4 | I-01 歌词驱动画面 | **命门**，但需要先定美术方向，不能盲写 |

| 6 | Q-02 分层视差 | 需先实测 `layer_decomposition` |

**明确不建议**：在只有 2 首歌的情况下扩意象库到 40 个。无法验证覆盖率，大概率白做。
