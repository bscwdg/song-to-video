## 一、目标需求（用户原话整理）

### 1. 输入

用户给一首歌，**歌词可有可无**。

### 2. 片段选择（必须问，不能默认切成整首）

| 情况 | 期望行为 |
|---|---|
| **给了歌词** | 按歌词结构列出可选片段，问用户要哪几段 / 用哪部分 |
| **没给歌词** | 先分析音乐（段落、能量、时长），再问用户要哪个片段 |

### 3. 细分与合成

把选中的片段**再细分**成更小的叙事单元（用户原话：**"像知识大赏那样"**），逐段做画面，最后合成一条完整视频。

也就是说流程是：

```
歌 + 可选歌词
   → 问要哪个片段
   → 片段再细分成镜头
   → 每镜出画面
   → 合成
```

### 4. 画面必须由歌词内容驱动

**这是最核心的诉求。** 用户明确指出：

> 「都没有根据歌词去绘图」
> 「我想要的就是……」
> 「这和我想要的不一致」

当前实现的实际行为是：构图 / 色板 / 运镜 / 主体**全部按镜号取模轮转**，与歌词文本无关。
→ 详见 `docs/ISSUES.md` 的 I-01。

### 5. 引入 AI（Seedream）

用户提出：**增加 AI 开关**。

- 用户明确要求用 AI → 直接走 AI
- 用户没说 → **skill 要主动问用户是否使用 AI**，再决定

开关必须落在**主入口**，不能像这次样片一样硬编码。

### 6. 动效质量

用户对第一版 AI 样片的评价：

> 「画面动效太生硬了」

已量化定位到三个原因（尖峰脉冲、光带回绕、多套运动各自叠加），**修复方案已写好但未实施**。

## 三、下一步的顺序建议

用户已明确要推倒重做，但基础设施（音频分析、QA、字幕）是好的，应保留。

1. **先修动效生硬**（方案已在 `motion.ts`，接入即可验证）
2. **做 AI 开关**（落在 `song2video.py`，`--ai auto|on|off`）
3. **做片段选择**（有歌词按乐句列候选，无歌词按段落列候选）
4. **建歌词 → 意象的映射**（这是命门，需要人工确认美术方向）
5. 风格一致性（参考图链式）
6. 分层视差（需实测 `layer_decomposition`）

**不要跳过第 4 步直接扩意象库。** 已确认：只有 2 首歌的情况下无法验证覆盖率。
